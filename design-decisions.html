Identity — the evidence ledger

Pulse proves — verdicts are executed evidence, not predictions. The visual identity follows that claim: data reads like ledger entries. Run IDs, SHAs, counts, percentages, and timestamps are set in 12px monospace; prose and labels stay sans-serif. The shell inherits the Aziron platform theme (slate neutrals, 1px borders, 6px radius, dense-but-calm) so Pulse sits inside the product without a seam, then the Aziron indigo accent (#3443f9) and three signature artifacts make it unmistakably Pulse.

The three artifacts — verdict chips, A–D grade blocks, and the receipt-styled attestation card (dashed rules, mono, watermark triangle) — appear on every surface where a verdict, a report card, or a signature exists. Nothing else is allowed to imitate them; scarcity is what makes them read as proof. See decisions in the log below.

Information architecture & nav model

All navigation lives in one place: the 48px Aziron product rail pinned on the left, expandable to 224px for labels (the expand state is remembered per browser, like the theme). The rail carries the Pulse nav map in seven groups, ordered by how often each is visited and how far it sits from a verdict: Overview → Analysis → Quality → Insights → Trust → Estate → Organization. The grouping mirrors the mental model "what happened → what it found → what it means → whether to trust it → where it applies → who runs it". A flat list of 17 items tested poorly; more than 8 groups fragmented the map.

Detail pages (run details, finding details, repository overview) are deliberately not in the rail — they are reached contextually from tables and feeds, which keeps the rail a stable map rather than a history. The breadcrumb always starts at Aziron and is never empty; the ⌘K palette jumps anywhere, so depth costs one keystroke, not a hunt. See , , and .

GitHub parity — the interaction grammar

A verification portal only earns its place if nobody has to leave it. Until Aug 3 the prototype was fluent in verdicts and foreign in everything around them: a pull request opened as an analysis page rather than a conversation, review comments posted one at a time, diffs had no expandable context or viewed markers, filters were dropdowns where reviewers expected a query, and the inbox listed events instead of grouping them by repository. Each gap was small. Together they sent people back to GitHub — and once there, they merged there too, so the verdict and the decision ended up on different screens (the exact failure set out to remove).

The decision is to adopt GitHub's interaction grammar wholesale rather than approximate it. Where GitHub has a settled convention, Pulse uses it unchanged — same tab order, same batching, same query syntax, same keys — and spends its design budget only where verification genuinely differs. Familiarity is not the goal in itself: the goal is that nothing on the screen costs a re-learn, so the only unfamiliar things left are the ones carrying information GitHub does not have. What stays Pulse-specific

Verdict chips
four values, not two — Advisory reports without blocking and Refused means the auditor declined to attest. A check is pass/fail; a verdict is executed evidence.
Attestation
every merge record points at a signed receipt (run 06cb9564, ed25519:7fd2…9c4e), not a green tick.
Enforcement gating
merge is a state machine over attested verdict + approvals + branch state, evaluated against the repo's Shadow / Advisory / Enforce mode.
Attention scores
the Action center ranks what to decide next instead of listing it chronologically.

Responsive & VS Code panel decisions

One system, three surfaces. Rather than a separate "mobile app" metaphor, the shell degrades in two honest steps: below 1013px the expanded rail overlays the page instead of pushing it (dismissed by Escape or a click outside, like any panel), then at ≤640px — or under ?surface=vscode at any width — the whole chrome compresses into a VS Code-panel profile. Both canvases ride the same Aziron indigo token set, re-valued by html[data-theme="dark"]. The panel is a first-class surface because verification verdicts are consumed where code is written — so the compact profile keeps the exact same terminology and hierarchy, only denser. Deliberately excluded

Autofix excluded

Pulse never edits code. The moment a verification product mutates the thing it verifies, its verdicts stop being independent evidence. Findings name a suggested owner (F-2381 → @priyar) instead.

Monetization vocabulary excluded

No commercial or cost-tier language anywhere in the product surface. Settings has no such tab. The prototype treats Pulse as fully provisioned for the Aziron workspace.

Dark theme shipped

Both canvases run off one token set — html[data-theme="dark"] re-values the same custom properties. Receipts, grade blocks, and verdict chips were re-calibrated on the dark canvas rather than duplicated. The default follows the OS; the topbar toggle remembers a choice.

Mutating dashboard widgets narrowed

Dashboards and lenses still only report state. Since Aug 3, explicit actions live in-portal on dedicated action surfaces — the PR workspace, the Action center, inbox quick actions — each verification-gated and audited, never a side effect of a chart.
